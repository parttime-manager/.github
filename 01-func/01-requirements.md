# 기능 명세 — PTManager

[README](../README.md) · [기술 구조](../03-tech/01-architecture.md) · [테스트 명세](../04-test/01-verification.md)

## 개요 및 범위

직원·사장 Android 앱에서 소규모 매장의 근무 편성·대타 합의·QR 근태·인건비를 공유한다. 1인 1매장(미소속 허용)을 지원하며 급여 이체·세무, 근로계약서, 다중 매장, 채용, iOS·웹, 공지 열람자 목록은 제외한다.

## 기능 요구사항

| 구분 | ID | 기능 |
| --- | --- | --- |
| 공통 | C-1~2 | 이메일·비밀번호 가입·로그인, JWT(액세스 1시간·리프레시 14일) 암호화 보관·자동 부착·갱신 |
| 공통 | C-3~5 | 공지 열람(레드 닷)·인수인계(재고·기기·손님), 알림 인박스·배지·설정, 프로필·멤버 조회·로그아웃 |
| 직원 (`EMPLOYEE`, 초대코드 신청, 5탭: 홈·스케줄·소통·통계·내 정보, `#0066CC`) | E-1~5 | 오늘·주간 근무, QR 출퇴근(`PRESENT`/`LATE`), 대타 요청·지원·조회, 실근태 반영 월 급여 |
| 사장 (`EMPLOYER`, 매장·초대코드 생성, 5탭: 홈·스케줄·승인·통계·내 정보, `#7048E8`) | R-1~7 | 매장·가입 승인/거절·방출·시급, 주간 초안·발행, 60초 회전 QR·고정 모드, 대타 승인/거절, 근태·인건비(월·주차·개인), 이미지 첨부 공지 |

## 업무 규칙

| 대상 | 규칙 |
| --- | --- |
| 대타 요청·승인 | 본인 근무만 요청하고 자기 요청 지원은 불가하다(근무당 `PENDING` 최대 1건). 승인 시 선택 지원은 `APPROVED`, 나머지는 `REJECTED`로 바꾸고 근무자를 재배정하며 `requester_id` 이력·결과 알림을 처리한다. |
| 대타 충돌 | 지원·승인 시 야간 교대를 보정해 기존 근무 및 같은 날 대기 지원(원 요청 거절 포함)과 시간 겹침을 검사한다. 동시 승인 시 조건부 갱신 영향 행이 0이면 롤백하며, 대기 대타가 있는 근무는 삭제할 수 없다. |
| QR·결근 | HMAC 서명·매장·만료를 검증하고, 종료 후 미체크인 근무는 매일 04:00 배치로 `ABSENT` 처리한다. |
| 급여 | 실근태를 반영하고 `ABSENT`는 제외하며 야간 교대를 보정한다. |

### 근무와 인건비

- 출퇴근이 모두 있고 퇴근 > 출근이면 실근무 시간, 그 외에는 편성 시간(종료 ≤ 시작이면 익일 연장)을 쓰며 현재 시급을 적용한다(시급 변경 시 과거 조회에도 반영).
- 월 합계는 총 근무 분 합산 후 시급을 곱하고, 주차 합계(1~7, 8~14, 15~21, 22~말일)는 근무별 원 미만 버림 후 합산하므로 두 합계가 다를 수 있다.
- 급여 집계에는 초안·미래 편성이 포함되며 사장 월 집계는 근무 없는 직원도 0원으로 표시한다. 예상 급여는 편성 시간 기준, 동료 목록은 동일 매장·날짜 기준이다.

### QR 출퇴근

- 발급 경로는 [REST API 명세](../03-tech/api.md#인증과-응답)를 따른다. 서버는 매장·서명·수명(기본 60초)과 인스턴스 메모리의 최신 발급 시각을 검사한다(재시작 시 메모리 초기화, 다중 인스턴스 미공유).
- 재발급은 이전 토큰을 무효화한다(수명 ≤ 0 인쇄용도 이후 재발급 시 무효, 같은 초 재발급은 동일 토큰). 사장 앱은 QR 화면 표시 중 45초마다 발급(실패 시 5초 후 재시도)하므로 인쇄 QR 사용 시 화면을 열지 않는다.

### 공지와 알림

- 공지 탭 진입 시 마지막 읽은 시각을 기록한다(인박스 읽음과 별개). 첨부는 선업로드 후 공지 저장 시 DB 행을 생성하며 취소·삭제 시 S3 파일은 남는다.
- 알림 대상: 공지(작성자 제외 전원), 대타 요청(요청자 제외 직원), 대타 승인(요청자·선택 지원자), 대타 거절(요청자), 가입 승인·거절(신청자), 근무 발행·발행 근무 수정(해당 직원; 초안·출퇴근·결근 배치는 미발송).
- 인박스는 푸시 설정과 무관하게 적재하고 커밋 후 푸시를 발송한다(미설정 시 기본 활성, 근무 변경 푸시는 설정 무관 발송).

## 보안 요구사항

- 비밀번호 해시·JWT 서명·서버 RBAC·매장 격리를 적용하고 시크릿(`local.properties`, `google-services.json`, 서명 키)은 커밋하지 않는다.
- HTTP는 디버그만 허용하며 릴리스는 HTTPS가 아니면 기동에 실패해야 한다.
- 편성·출근 판정·04:00 결근 배치는 `Asia/Seoul` 기준이며 JVM 시간대를 [배포 설정](../05-ops/01-deploy.md#2-ec2-초기-설정)에서 맞춘다.

## 현재 구현과의 차이

초안 비공개가 요구사항이나 현재는 직원 근무 목록만 발행 여부를 검사하고 상세·출퇴근·급여는 검사하지 않는다. 일반 근무 편성의 중복 검사도 당일 일반 근무만 비교하므로 초안 비공개와 야간·날짜 경계 충돌 방지는 보완이 필요하다.

## 완료 기준

### 기능 검증

[Backend 데모 계정](https://github.com/parttime-manager/backend#데모-계정)과 시드 데이터로 재현한다.

1. `applicant@ptmanager.test`의 `CAFE01` 가입 신청 → 사장 승인 → 멤버 노출.
2. 다음 주 근무 초안 작성 → 발행 → 직원 확인.
3. 사장 QR 발급 → 직원 출근 판정 → 퇴근.
4. 대타 요청 → 2명 지원 → 1명 승인 → 근무자 교체 및 요청자·승인 지원자 알림.
5. 사장 월·주차 인건비와 직원 급여에 실근태 반영.

### 운영 검증

[배포 가이드](../05-ops/01-deploy.md)에 따라 확인한다.

1. 수동 배포 후 `/actuator/health`가 `UP`을 반환하고, 필수 환경변수 누락 시 prod 기동이 실패한다.
2. 두 앱 HTTPS 릴리스에서 로그인·대타 승인 푸시·재접속 후 첨부 조회에 성공한다.
